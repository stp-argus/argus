## 2. A2A Protocol (Linux Foundation)

- **Spec: v1.0.1** (2026-05-28); **1.0.0 GA 2026-03-12**, major breaking changes vs 0.x; `spec/a2a.proto` is now the normative source **V** ([releases](https://github.com/a2aproject/A2A/releases), [spec](https://a2a-protocol.org/latest/specification/)).
- **Identity fields (V, normative text):** `Message.messageId`/`contextId`/`taskId` (camelCase in JSON); `Task.id` (server-generated UUID) + `contextId`. Spec: "All tasks and messages with the same `contextId` SHOULD be treated as part of the same conversational session"; servers MAY mint `contextId` and MUST return it; MUST reject mismatched `contextId`/`taskId`. → **contextId = Conversation, taskId = RunID, spec-blessed.** New 1.0 `tenant` field on `SendMessageRequest` = extra Principal signal.
- **Transport:** three equivalent bindings, none mandatory — JSON-RPC 2.0/HTTP, gRPC, HTTP+JSON REST (`POST /message:send`, media type `application/a2a+json`). **Breaking: JSON-RPC methods renamed to PascalCase** (`SendMessage`, `GetTask`…; 0.x `message/send` is gone) — a parser must handle both generations **V**.
- **Proxy extraction: yes** — identity sits at `params.message.{contextId,taskId,messageId}` in JSON bodies (and SSE streams); NOT in headers. Headers carry only `A2A-Version` (MUST for 1.0 clients) and `A2A-Extensions` **V**.
- **Adoption:** LF press 2026-04-09: 150+ orgs; Azure AI Foundry/Copilot Studio, AWS Bedrock AgentCore, Google Cloud; LangGraph/CrewAI named **V**; ADK/LlamaIndex/Semantic Kernel/AutoGen/MAF support **R**.

## 3. MCP

- **Current stable revision: 2025-11-25** (experimental tasks, tools-in-sampling, URL elicitation) **V** ([changelog](https://modelcontextprotocol.io/specification/latest/changelog)).
- **⚠ Critical: the 2026-07-28 revision (RC published, final ~4 weeks out) makes MCP stateless and REMOVES `Mcp-Session-Id` and the `initialize` handshake entirely** — client metadata moves to per-request `_meta`; state becomes explicit tool-minted handles **V** ([RC post](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)). Legacy header traffic will persist (12-month deprecation policy), but do not architect on it.
- Today's semantics (**V**, transports page): server MAY assign `MCP-Session-Id` at init; client MUST echo it on every request; DELETE ends session; `MCP-Protocol-Version` header MUST be sent post-init. Tasks: receiver-generated `taskId`, correlated via `_meta["io.modelcontextprotocol/related-task"]`.
- **Runaway vector verdict:** plain tool-call loops are already visible at the LLM tap (each iteration needs an LLM call). The genuinely distinct vector is **sampling + tools (2025-11-25)**: the spec documents a server-driven "Multi-turn Tool Loop" ("repeats as many times as needed") guarded only by SHOULD-level iteration limits — **a runaway MCP server can pump unbounded LLM calls through the agent host's credentials**, and on the wire it looks like the agent's own traffic **V** ([sampling](https://modelcontextprotocol.io/specification/2025-11-25/client/sampling)). Argus should model "MCP-server-driven spend" as a separate attribution class.

## 4. OTel GenAI semantic conventions

- **Still NOT stable.** In semconv **v1.42.0 (2026-06-12)** all `gen_ai.*` conventions were **deprecated in the main repo and moved to a new dedicated repo** [open-telemetry/semantic-conventions-genai](https://github.com/open-telemetry/semantic-conventions-genai) — which has **zero releases/tags** as of 2026-07-02; everything remains Development stability **V**.
- Current attribute names (**V**, new-repo registry): `gen_ai.conversation.id` ("conversation (session, thread)"), `gen_ai.agent.id/.name/.version`, **`gen_ai.provider.name`** (replaced `gen_ai.system`, which no longer exists), `gen_ai.operation.name` ∈ {`chat`, `invoke_agent`, `execute_tool`, `create_agent`, …}; newer: `gen_ai.conversation.compacted`, `gen_ai.workflow.name`. MCP semconv landed in v1.39.0 (2026-01-12).
- **No convention exists for conversation-id-in-HTTP-header.** The community pattern is W3C `baggage` (e.g. `gen_ai.conversation.id=…`) + `traceparent` — readable by a proxy **only if the app opts into httpx/HTTP instrumentation** (**R**). Practical Argus stance: read `traceparent`/`baggage` opportunistically; emit `gen_ai.*` attributes on Argus's own telemetry, pinned to a semconv version since it may still rename.

## 6. Implications for Argus's coverage strategy

**Provider-level identity fields Argus can always parse (independently verified):**
- OpenAI Chat Completions: `user` (being replaced), **`safety_identifier`**, **`prompt_cache_key`**, `metadata`, `store` **V** ([API ref](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create); platform.openai.com fetch was 403).
- OpenAI Responses: `conversation` (conv_… — **strongest conversation key on the wire**), `previous_response_id` (mutually exclusive with `conversation`), `metadata`, `store` **V** (SDK types). ⚠ With `previous_response_id`+`store=true` the proxy sees only the tail — conversation reconstruction = linked list of response ids, and prefix-hash dedup breaks; Argus needs a response-id chain tracker for `/v1/responses`.
- Anthropic Messages: `metadata.user_id` (opaque id), `anthropic-user-profile-id` header (beta) **V** ([API ref](https://platform.claude.com/docs/en/api/messages)).
- LiteLLM proxy: body `litellm_session_id` (via `extra_body`/`metadata`); headers `x-litellm-tags`, `x-litellm-spend-logs-metadata`, `x-litellm-customer-id`/`x-litellm-end-user-id`; `/responses` sessions via `previous_response_id` **V** ([request_headers](https://docs.litellm.ai/docs/proxy/request_headers), [session logs](https://docs.litellm.ai/docs/proxy/ui_logs_sessions)). Note: `litellm_session_id` is proxy-local, not forwarded upstream — Argus must sit **at or behind** the LiteLLM hop, or be the LiteLLM callback, to see it.

**Coverage buckets:**

**(a) Transparent OpenAI/Anthropic-compatible proxy covers (9/10 frameworks via one env var):** LangChain/LangGraph (`OPENAI_BASE_URL`/`ANTHROPIC_BASE_URL`), OpenAI Agents SDK (`OPENAI_BASE_URL`; must parse `/v1/responses` and optionally `/v1/traces/ingest` for trace_id/group_id), CrewAI (`OPENAI_BASE_URL`; NOT `OPENAI_API_BASE` on the native path), AutoGen 0.7 / AG2 / MAF (`base_url`/`OPENAI_BASE_URL`), Claude Agent SDK (`ANTHROPIC_BASE_URL` — plus free 3-axis identity from `x-claude-code-session-id`/`x-claude-code-agent-id` headers; SSE streaming pass-through is mandatory, don't mutate bodies), Pydantic AI (`base_url`; must parse Responses), smolagents API paths (`api_base`). **Requirement this imposes: Argus must parse the Responses API, not just Chat Completions** — it's now the default for OpenAI Agents SDK, Pydantic AI, and MAF.

**(b) LiteLLM callback/proxy tier adds:** ADK via `LiteLlm(api_base=)` (the sanctioned non-Gemini route), CrewAI's long-tail providers, smolagents `LiteLLMModel`, plus Bedrock/Vertex/100+ providers normalized to OpenAI format with `litellm_session_id`/`x-litellm-*` identity enrichment. Positioning Argus as a LiteLLM upstream (LiteLLM's `forward_client_headers_to_llm_api` forwards `x-*` headers) or logging callback is the cheapest multiplier for non-OpenAI/Anthropic wire formats.

**(c) Gaps (no HTTP or non-parseable wire format):** ADK's **default** google-genai/Gemini path (needs a Gemini-format parser or the LiteLlm detour), Bedrock-native paths (smolagents `AmazonBedrockModel`, Pydantic AI `BedrockConverseModel`, Claude Agent SDK Bedrock/Vertex modes — different URL shapes/body dialects), smolagents local models (`TransformersModel`/`MLXModel`/`VLLMModel` — zero HTTP), and the OpenAI Agents SDK **websocket** Responses transport.

**Strategic conclusions:**
1. **Don't chase per-framework wire identity — it mostly doesn't exist.** Content-derived conversation identity (prefix hashing) plus auth-derived Principal is correct for ~7/10 frameworks; the two special cases worth native support are Claude Code's `x-claude-code-*` headers and Responses-API `conversation`/`previous_response_id` chains.
2. **Ship a documented "identity injection" convention** (e.g. `x-argus-session-id`) and per-framework one-liners — every framework verified here has an escape hatch: LangChain `default_headers`/`extra_body`, Agents SDK `ModelSettings.extra_headers`, CrewAI `BaseInterceptor`, AG2/MAF `default_headers`, Pydantic AI injected SDK client, smolagents `client_kwargs`, Claude Code `ANTHROPIC_CUSTOM_HEADERS`. Also read `traceparent`/`baggage` opportunistically.
3. **Responses API support is now table stakes; a Gemini parser is the single highest-coverage addition after that** (unlocks ADK's default path).
4. Frameworks' own guards are loosening or opt-in (LangGraph recursion default 25→1000, Agents SDK `max_turns=None` allowed, AG2's "budget" is context-trimming) — only Claude Agent SDK (`max_budget_usd`) and ADK (`max_llm_calls=500`) have real built-in backstops. This is the positioning argument for external, declarative enforcement.
5. **A2A taps are worth building** (stable 1.0 `contextId`/`taskId` = Conversation/RunID from JSON bodies, both directions, PascalCase methods); **MCP taps should target the sampling-loop vector, not `Mcp-Session-Id`** (deleted in the 2026-07-28 revision); emit OTel `gen_ai.*` attributes but pin the version — conventions are still Development and just changed repos.
